# Личный сайт me.romb-web.ru

Лендинг работает в том же Laravel-приложении и базе данных, что и romb-web.ru.
Маршрут `/` для домена `PERSONAL_DOMAIN` зарегистрирован перед маршрутами студии.
Страницы студии и `/admin` на личном поддомене возвращают 404.
Админка остаётся на основном домене: `/admin/personal-page`, пункт «Личный сайт».
Дополнительные Composer-пакеты не требуются. Собранный фронтенд включён в Git.

## Настройка поддомена

1. В DNS добавить `me` с A-записью на IP действующего сайта. Если используется
   AAAA-запись, IPv6 должен обслуживаться тем же хостингом.
2. В панели REG.RU добавить `me.romb-web.ru` и указать **тот же каталог public**:
   `/var/www/u1181220/data/www/romb-web.ru/public`. Не создавать отдельную копию
   Laravel и не направлять поддомен в корень проекта.
3. Подключить SSL-сертификат для `me.romb-web.ru` и перенаправление HTTP на HTTPS.
4. В `.env` основного приложения оставить `APP_URL=https://romb-web.ru`.
   `PERSONAL_DOMAIN=me.romb-web.ru` задан по умолчанию; при необходимости его можно
   указать явно. Значение — имя хоста без протокола, пути и завершающего `/`.
   Оставить `SESSION_DOMAIN` пустым или ограниченным основным доменом; общей
   авторизации между поддоменами для личного сайта не требуется.

## Выкладка после merge

Сначала обновить локальную копию на ветке `main`, затем выполнить на сервере:

```bash
set +e
(
    set -e
    cd ~/www/romb-web.ru
    test -f artisan
    test "$(git branch --show-current)" = main
    git pull --ff-only origin main
    /opt/php/8.5/bin/php artisan migrate --force
    /opt/php/8.5/bin/php artisan db:seed --class=PersonalPageSeeder --force
    /opt/php/8.5/bin/php artisan config:clear
    /opt/php/8.5/bin/php artisan route:clear
    /opt/php/8.5/bin/php artisan view:clear
    /opt/php/8.5/bin/php artisan view:cache
)
```

Используется CLI PHP 8.5: команда `php` на текущем сервере запускает PHP 8.2,
которого недостаточно для установленных зависимостей. `set -e` действует внутри
подоболочки, поэтому ошибка команды не закрывает SSH-сессию.
Если `git pull` сообщает о пересечении с локальными изменениями, остановиться и
проверить их; не применять `reset --hard` и не восстанавливать старый stash
шаблонов главной страницы.

Миграция создаёт только таблицу `personal_pages`. Выполнять **именно**
`PersonalPageSeeder`, а не общий `DatabaseSeeder`: начальные тексты, контакты,
опыт и проекты создаются один раз, повторный запуск сохраняет правки администратора.
Фотография из резюме включена в `public/images`.
Для загрузки новых фото через админку должна существовать стандартная ссылка
`public/storage` → `storage/app/public`. Если ссылки ещё нет, выполнить
`/opt/php/8.5/bin/php artisan storage:link`. Проверить доступность загруженного файла
и права записи в `storage/app/public` для пользователя сайта.

## Редактирование и проверка

- Войти в админку основного сайта и открыть «Личный сайт».
- Редактируются главный экран, фото, текст о себе, группы навыков, опыт, проекты,
  контакты и SEO. Опыт, навыки и проекты можно добавлять, удалять, перемещать
  кнопками и скрывать. Обложки проектов необязательны.
- Telegram задаётся как `@username`, ссылки проектов — как `https://example.com`.
  Телефон, Telegram и почту можно оставить пустыми, соответствующие ссылки скроются.
- Сохранение сразу обновляет публичный лендинг. Выключение «Страница опубликована»
  скрывает его с ответом 404. Перед первым открытием админки выполнить seeder.
- В исходном списке указан `tileofapsin.ru`: адрес не подтверждён, поэтому проект
  Tile of Spain добавлен без внешней ссылки. Указать точный URL через админку.
- Проверить HTTPS, `https://me.romb-web.ru/`, контакты, ссылки проектов, мобильное
  меню, сохранение формы и показ/скрытие карточки. На `me.romb-web.ru/articles` и
  `me.romb-web.ru/admin` должен быть 404; основные страницы romb-web.ru продолжают
  работать. Анимации отключаются при системной настройке уменьшения движения.
